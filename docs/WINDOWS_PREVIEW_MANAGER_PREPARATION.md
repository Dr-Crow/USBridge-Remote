viewer gate proved generated changing pixels and natural cleanup through the

## Eligibility is an observation, not permission

Native query `9f75806d381b3ef1a36931709ca1624e28134b08`, CircleCI job402,
completed successfully. Its current token was elevated, while the session and
window station were interactive and visible. Therefore `eligible=false`.
The query makes no account, token, privilege, desktop, station or security
changes. An ordinary non-elevated VM desktop passed all six facts using the exact
cross-built probe. The internal Windows Manager now applies this verified
read-only predicate at every Start; its settings action remains Linux-only.
An elevated test runner is not a reason to weaken the non-elevated requirement.

## Prepared next gate

`prepare_windows_preview_manager.py` first checks the exact same-commit native
CLI media/pixel/cleanup receipt. It then stages the source and viewer under
separate, exact hash-pinned roles, with their complete DLL closures. No process
is executed by staging. The files stay in job-local work; only bounded JSON
receipts are published. The frozen source remains the previously public
`2e07af3484369bc68bc8091d5a04969867eff0f9`; no private component is fetched.

The opt-in `windows && source_preview_manager_acceptance` tests use production
`New`, `Start`, component installation, source and viewer launchers. Their
read-only observations cannot replace consent, eligibility, children or frames.
The actual test requires a genuinely eligible native process and the production
Windows gate. It is deliberately not selected in the elevated hosted job. Its separate
file-pin, manifest, pixel-classification and cleanup-accounting tests execute
there before the expensive renderer build.

Once an eligible environment is established, the full test covers missing
consent, overlap rejection, fresh sessions, actual owned changing pixels,
Manager.Stop and parent cancellation, joined children, removed windows and
rebindable ports. Incomplete cleanup remains a failure and cannot produce a
clean receipt. This tests Manager composition; `actual_app_new` remains false.
The actual Windows App.New/settings dialog, explicit consent interaction,
Stop/Close/close-to-tray/quit and independent current-private-component run are
subsequent required gates. No source-only onboarding, remote pairing, physical
desktop, GPU or full-product parity is claimed.
